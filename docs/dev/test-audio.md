# 検証用音声セット（日本語会話・Watch 録音を模した加工）

実機なしで「Watch で録音 → スマホで文字起こし → ローカルに蓄積」の品質を確かめるための、**正解テキスト付き**の音声セット（#56）。
すべてこの PC の中で合成・加工・評価する。音声やテキストをネットワークに送ることはない（ダウンロードはモデルの取得のみ）。

- コーパス（会話台本）: [`tools/test-audio/corpus/`](../../tools/test-audio/corpus/)
- 生成スクリプト: [`tools/test-audio/generate.py`](../../tools/test-audio/generate.py)（`tts.py` 音声合成、`effects.py` 加工、`corpus.py` 台本の読み込み）
- 評価コマンド: `./gradlew :tools:harness:run --args="evaluate <manifest.json> <作業ディレクトリ>"`（[`TestSetEvaluator.kt`](../../tools/harness/src/main/kotlin/app/watchaudio/harness/TestSetEvaluator.kt)、[`Scoring.kt`](../../tools/harness/src/main/kotlin/app/watchaudio/harness/Scoring.kt)）
- 小さな固定サンプル（コミット済み）: [`tools/test-audio/fixtures/`](../../tools/test-audio/fixtures/)

## 1. 生成と評価の手順

```bash
# 1. 音声合成の準備（venv・モデルの取得。tools/test-audio/.venv と cache/ は gitignore）
tools/test-audio/download-models.sh

# 2. 音声セットの生成（初回は音声合成に約 10 分、加工・書き出しに約 4 分。出力は tools/test-audio/cache/out/、約 300 MB）
tools/test-audio/.venv/bin/python tools/test-audio/generate.py
#   条件を絞る:            --only clean,cafe --no-day
#   ReazonSpeech も使う:   --reazon-manifest research/asr-benchmark/data/manifest.jsonl
#                          （research/asr-benchmark の prepare_data.py で取得済みのテストデータを使う）
#   英語・日英混在（#81）:  --fleurs-manifest research/asr-benchmark/data/manifest.jsonl
#                          （同じく取得済みの FLEURS en 120 文を使う。--only english_clean,english_wrist,mixed_clean,mixed_wrist）

# 3. ハーネスで評価（ASR モデルは tools/harness/download-models.sh で取得。全条件で約 15 分）
./gradlew --max-workers=2 :tools:harness:run \
  --args="evaluate tools/test-audio/cache/out/manifest.json build/test-audio-eval"
#   特定の録音だけ:  --args="evaluate tools/test-audio/cache/out/manifest.json build/test-audio-eval clean day"
#   録音ごとに別々に実行してもよい（メモリが少ない環境向け）。results.md は作業ディレクトリ内の
#   評価済みの録音すべてをまとめ直す
#   VAD・区間の切り出しの設定を変えて比べる（再コンパイル不要。名前は VadSettings のプロパティ名、既定はアプリと同じ値）:
#   --args="evaluate tools/test-audio/cache/out/manifest.json build/eval-th03 --vad threshold=0.3,negThreshold=0.3 office cafe"
#   （--vad は繰り返してもよい。設定ごとに作業ディレクトリを分ける。使った設定は最初に「VAD: VadSettings(...)」と表示される）
#   誤認識の除去（FalsePositiveFilter、#105）は既定でアプリと同じものが効く。比べるときは:
#   --args="evaluate tools/test-audio/cache/out/manifest.json build/eval-nofilter --filter off"           （何も捨てない）
#   --args="evaluate tools/test-audio/cache/out/manifest.json build/eval-f5 --filter minLevelAboveNoiseDb=5"（値を変える）
#   除去の規則の候補を、文字起こしをやり直さずに比べる（--filter off で評価した作業ディレクトリが対象）:
#   --args="filter-study tools/test-audio/cache/out/manifest.json build/eval-nofilter"
#   録音形式（コーデック・ビットレートなど。名前は RecordingFormat のプロパティ名、既定は Watch と同じ
#   RecordingFormat.CURRENT = AAC-LC 16 kHz mono 24 kbps・5 分チャンク）を変えて比べる（#52）:
#   --args="evaluate tools/test-audio/cache/out/manifest.json build/eval-opus16 --format codec=opus,bitrateBps=16000"
#   （AAC は ffmpeg 内蔵の aac、Opus は libopus（Ogg）で符号化する。保存された音声のサイズは録音ごとの行に MB/h で出る）
#   英語も文字起こしする（アプリの設定「英語も文字起こしする」と同じ。SenseVoice が要る、#81）:
#   --args="evaluate tools/test-audio/cache/out/manifest.json build/eval-en --english on"
#   （LanguageRouting の値を変える: --english maxPrimaryCharsPerSecond=Infinity は全区間で SenseVoice を動かす）
#   固定サンプルで動作確認（1 分×3 条件、数十秒で終わる）:
#   --args="evaluate tools/test-audio/fixtures/manifest.json build/test-audio-fixture"
```

評価は CI では実行しない（時間がかかり、モデルと生成音声が必要なため）。CI は既存の短い E2E（`EndToEndTest`）と、採点ロジックの単体テスト（`ScoringTest`、モデル不要）だけを実行する。

## 2. 音声セットの中身

### 会話コーパス

日常会話 16 本・505 発話（台本は約 9,100 字、合成すると発話 24 分）。オフィスの定例・1on1・デザインレビュー、家族の朝食・夫婦の予定・子どもの宿題、スーパー・洋服屋・不動産屋・病院、カフェ・散歩、電話（歯医者・再配達・母）。
相づち（「うん」「はい」「へえ」）、言いよどみ（「えっと」「うーん」）、短い話者交代、数字・日付・金額・電話番号・人名、カタカナ語と一部の英字（PDF ではなく {Zoom|ズーム} のように読みを指定）を含む。

台本の書式（`corpus/*.txt`）:

```
# title: 週次定例ミーティング
# scene: office
# speakers: A=jf_alpha B=jm_kumo C=ojt_m001:phone
A: リリース日は11月20日のままで大丈夫そうですか？
B: {Zoom|ズーム}のリンクを{Slack|スラック}に貼っておきました。
```

- 話者 **A は Watch を着けている本人**（マイクに最も近い）。`:phone` は電話の相手（スマホのスピーカー越しの声）。
- `{表記|よみ}` は音声合成に読ませる読み。正解テキストは「表記」側。

### 会話の組み立て

文ごとに合成し、同じ発話内の文の間に 0.25〜0.5 秒の間を入れる。話者交代の間は平均 0.35 秒（0.08〜1.2 秒）、ときどき 1.5〜3 秒の沈黙、短い相づちの 35% は前の発話の終わりに 0.15〜0.5 秒かぶせる。発話ごとに音量を ±2 dB ばらつかせ、話者ごとに話速を 0.95〜1.1 倍にする。会話と会話の間は 4〜8 秒。乱数は `--seed`（既定 56）で固定され、同じ条件なら毎回同じ音声になる。

### 条件

すべての条件で同じ 16 会話（会話間の間を含め 29.3 分）を使い、加工だけを変える。評価時には WatchSimulator が Watch と同じく **5 分チャンク・AAC-LC 24 kbps** に符号化する（`.m4a` の出力も同じ設定）。

| ID | 内容 |
| --- | --- |
| `clean` | 近接・無雑音（基準）。本人 -26 dBFS、相手 -3 dB、電話の相手 -8 dB（300〜3,400 Hz の帯域制限と軽い歪み） |
| `wrist` | 腕の位置: 本人 -6 dB・残響 RT60 0.3 秒（直接音優勢 DRR +8 dB）、相手 -14 dB・RT60 0.5 秒（DRR +1 dB）、電話 -16 dB |
| `office` | `wrist` ＋ オフィス雑音（空調のピンク/ブラウンノイズ、キーボード、遠くの話し声）、本人の声に対して SNR 15 dB |
| `cafe` | `wrist` ＋ カフェ雑音（8 人分のざわめき、食器の音）、SNR 10 dB |
| `outdoor` | `wrist` ＋ 屋外雑音（車の通過、ブラウンノイズ、マイクに当たる風）、SNR 8 dB |
| `rub` | `wrist` ＋ 袖やベルトの擦れ・腕の動きの衝撃音（平均 6 回/分、0.25〜1.8 秒、本人の声の ±6 dB） |
| `day` | 約 1 時間の「1 日の一部」: 朝食（家）→ 通勤（屋外、会話なし）→ 定例・1on1（オフィス）→ 15 分の無音（デスクワーク）→ 昼休み（カフェ）→ 電話・レビュー（オフィス）→ 散歩（屋外）→ 買い物（店）→ 電話・宿題（家）→ 無音。場面ごとの雑音、全体に軽い擦れ音（1.5 回/分） |
| `reazon_clean`（任意） | ReazonSpeech テストセット 150 文（テレビ音声）を 2.5〜4 秒の無音でつないだもの |
| `reazon_cafe`（任意） | 同じ 150 文を相手の位置（-14 dB・残響）＋ カフェ雑音 |
| `english_clean`（任意、#81） | 英語の会話: FLEURS en テスト（英語の読み上げ、実際の人の声）60 文を 6 文ずつ 10 会話にし、装着者と相手が交互に話す（間 0.2〜1.2 秒、会話の間 4〜8 秒）。近接。11.3 分。会話ごとに WER で採点 |
| `english_wrist`（任意） | 同じ 60 文 ＋ `wrist` の加工 |
| `mixed_clean`（任意、#81） | 日英混在: コーパスの日本語の発話（合成音声、会話の順のまま）1〜3 つごとに英語の発話（FLEURS en、残りの 60 文。装着者か相手）を 1 つ挟む。発話の間 0.6〜1.5 秒。日本語 114・英語 60 発話、18.6 分。発話ごとに採点（日本語は CER、英語は WER）し、保存された言語も確かめる |
| `mixed_wrist`（任意） | 同じ ＋ `wrist` の加工 |

全条件でマイクの自己雑音（-70 dBFS）と 60 Hz のハイパスを入れる。無音区間は Watch の無音判定（RMS 0.003 ≒ -50 dBFS）を下回るので、`day` の長い無音では Watch が音声なしのチャンクを送る経路も通る。

雑音はすべて `effects.py` で数式から生成している（ピンク/ブラウンノイズ、フィルタしたノイズのバースト、減衰する正弦波など）。ざわめきは本コーパスの合成音声を重ねて残響をかけたもの。外部の録音素材は使っていないので、雑音にライセンス上の制約はない。

## 3. 採点の方法

- **CER（文字誤り率）**: 会話ごとに、正解の発話を時刻順に並べた文字列と、その会話の時間帯（±1 秒）と最も重なる文字起こし区間を時刻順に並べた文字列を編集距離で比べる。会話の外（無音・雑音だけの区間）で出た文字起こしは全て挿入誤りとして全体 CER に加える（「発話外の誤認識」列にも文字数を示す）。
  - 正規化: NFKC → 小文字化 → 句読点・空白・記号を除去 → **漢数字を算用数字に統一**（ASR は「三千四百八十円」、正解は「3480円」と書くため）。かな/漢字の表記揺れ（「きょう」と「今日」など）は誤りとして数える。
  - 「CER 装着者」「CER 相手」は、誤りを正解側の文字の話者に割り当てて分けたもの（相手 = 同室の相手と電話の相手）。
- **WER（単語誤り率、英語、#81）**: 正解が英語（`lang: en`）の会話・発話は単語で比べる。正規化は M0-5 と同じ: NFKC → 小文字化 → ハイフンを空白に → 英数字と空白以外を除去 → 空白で単語に分ける。数字の表記（"twenty" と "20"）は統一しない。CER の列には日本語（英語以外）の発話だけが入り、発話外の誤認識は CER に数える。
- **言語の誤り（#81）**: 各正解発話と最も重なる保存セグメントの言語（`transcript_segment.lang`）が、正解の言語と違う発話の数（`ja 2/480` = 日本語 480 発話のうち 2 つが別の言語で保存された）。
- **検出漏れ**: どの文字起こし区間とも時間が重ならない正解発話の割合（括弧内は件数）。VAD が複数の発話を 1 区間にまとめても漏れにはならない。
- **処理時間・RTF**: `TranscriptionPipeline.processPending()` の実時間と、それを音声長で割った値（この PC の 2 スレッド。実機の速度は別途）。

- **符号化器**: ffmpeg 6.1.1 の内蔵 `aac`（AAC-LC、.m4a）と libopus 1.4（Ogg、既定の VBR・`application=audio`）。Watch の実機はそれぞれのプラットフォームの符号化器（Wear OS は `MediaRecorder`/`MediaCodec` の AAC、watchOS は `AVAudioRecorder` の AAC）を使うので、**サイズも音質も実機とは一致しない**。特に低ビットレートでの振る舞いは符号化器ごとに大きく違う。
- **サイズ**: AAC はほぼ固定ビットレート（公称の約 1.03 倍、24 kbps で 11.1 MB/時。条件による差は 1% 未満）。Opus は可変ビットレートで公称より小さく、内容で変わる（16 kbps で 6.6〜7.0 MB/時、`day` は 6.2 MB/時）。無音も含めて 1 時間を連続で符号化すると（`day.flac` 全体）、AAC 24 kbps 11.1・Opus 16 kbps 6.0・Opus 24 kbps 9.2 MB/時。
- **AAC 16 kbps は使えない（この符号化器では）**: ffmpeg の `aac` は 16 kbps で 4 kHz より上を完全に削る（4〜8 kHz のエネルギーが -64〜-80 dB）。発話の検出（Silero VAD）が雑音下で声を見失い、office・cafe・outdoor で発話の 52〜100%（day で 52%）を取りこぼした。正解区間で切っても CER は 24 kbps より平均 4 ポイント悪い。24 kbps では帯域は保たれる（8 kHz まで ±1 dB 以内）。
- **Opus 16 kbps**: サイズは AAC 24 kbps の 6 割（-40%）。正解区間で切った CER は平均 +1.0 ポイント（cafe +2.8・clean +2.3、outdoor・reazon_clean はむしろ良い）。全体の CER は条件で上下する（cafe は 40.9% → 36.9% と良いが、これは AAC 24 kbps の cafe で区間の切り方が外れて 11 発話を取りこぼしたためで、符号化の差ではない）。
- **Opus 24 kbps** は AAC 24 kbps とほぼ同じ CER でサイズは 1 割弱小さいだけ。**Opus 12 kbps** は正解区間で切った CER が平均 +2.8 ポイント。
- clean だけは Opus がどのビットレートでも約 15% で、AAC（12〜13%）より 2〜3 ポイント悪い。差は主に装着者の声（全体の CER の装着者分が AAC 24 kbps 13.1% → Opus 17〜18%）。原因は調べていない（腕の位置や雑音のある条件では差は小さいか逆転する）。
- 全体の CER は VAD・区間の切り方を通るので、同じ符号化でも条件によって数ポイント揺れる（AAC 32 kbps と 24 kbps の cafe 31.7% / 40.9% など）。符号化どうしの比較には「正解区間で切った CER」の方が安定している。
- AAC-LC 24 kbps の行は「現在（#105 の修正後）」の表と全条件で一致した（評価は決定的）。

- **しきい値を下げると相手の声が戻る**: カフェ・屋外の相手の声（装着者より 8 dB 小さく、雑音との差は 2〜7 dB）は、Silero の確率が 0.3 に届かず検出漏れや途中切れになっていた（カフェの検出漏れ 42 → 10 発話）。ただし sherpa-onnx の VAD は終了のしきい値が「開始 − 0.15」に固定のため、0.15 に下げると 0.01 未満でしか区間が終わらず、reazon_clean が 13.3% に悪化した。そこで確率から区間を作る処理を自前にし、開始・終了とも 0.15 にした。
- **一定の長さで区切らない**: 最小無音を 2 秒にすると区間が長くなり、VAD の「最大 20 秒」で語の途中で切られる所が増えて clean が 15.0% → 15.9% に悪化した。この区切りをやめ（長い区間は `padSpeechSpans` が間や最も静かな点で 20 秒以下に分ける）、間の判定の基準になる「大きい音」を区間全体ではなく前後 1 秒で測るようにして解消した。
- 試したが採用しなかったもの: 長い間の中央を捨てて前後 0.3 秒だけ残す（カフェ 41.7% → 43.3%）、上限を 8 秒にする（変化なし）。話者の切り替わりの検出（speaker embedding）とノイズ抑制は、目標を満たしたので試していない（モデルの追加が必要）。

### 読み取れること

- **ハーネスと採点は妥当**: ReazonSpeech（1 文ずつ間が空いた音声）では CER 10.3%（修正前 9.7%）、M0-5 スパイクの 7.1%（AAC 24 kbps、正規化の違いあり）と近い。`day` では 15 分・7 分の無音から Watch が無音チャンク 3 個を音声なしで送り、取り込み・文字起こしが正しくスキップした。
- **会話の文が抜け落ちる問題（#68）は、静かな条件では解消した**: 修正前は、合成会話で正解区間で切れば CER 12〜31% なのに、パイプラインでは 54〜87% だった。誤りのほとんどは脱落（削除誤り）だった。原因は 3 つ重なっていた。
  1. 話者交代の間（平均 0.35 秒）が VAD の最小無音 0.5 秒より短く、複数人の発話が 1 区間にまとまる。
  2. VAD が最大 20 秒で区切った区間同士は隙間がないため、`padSpeechSpans` が前後 0.3 秒の余白を付けると重なって**再び 1 区間に結合される**。結果、認識器への入力が最大 109 秒になる（`clean` の区間長の中央値 11 秒・最大 70 秒、`wrist` は中央値 31 秒・最大 109 秒）。
  3. Zipformer ReazonSpeech は、話者交代を含む入力の途中の文をまとめて落とす。本物の音声（ReazonSpeech・FLEURS の発話を 0.35 秒の間でつないだ 20〜70 秒の音声）でも同じく大半の文が消える。入力を 20 秒以下にしても、中央値 10 秒・複数の話者交代を含む入力では CER 44%（clean）のままで、話者交代ごとに切る必要があった。

  さらに、`wrist` では VAD の最小無音を短くしても区間が切れなかった。残響のある音声では、間の音量は無音（-70 dBFS）まで下がっているのに、Silero の確率が 1 秒以上しきい値を下回らない。そこで VAD 区間の中の「間」をエネルギーで探して切るようにした（[02 §6.3](../architecture/02-architecture.md#発話区間の切り出しandroid--jvm-ハーネス6871)）。修正後は clean 15.0%・wrist 21.4%・rub 27.0% で、正解区間で切った場合との差は 3〜6 ポイント。
- **reazon_clean のわずかな悪化（9.7% → 10.3%）は主に挿入誤り**: テレビ音声の各クリップには、正解テキストに含まれない前後の発話が入っていることがある。区間を細かく切ると、修正前は落ちていたそうした発話も文字になり、挿入誤りとして数えられる（簡易な集計で、0.15 秒の設定では削除誤り 4.5% → 4.7% に対し挿入誤り 3.3% → 4.8%）。文の途中の短い間でも切れるので、文脈が減って誤る例もある。
- **雑音のある条件（#71）**: #68 の修正後も、オフィス・カフェ・屋外・1 日分では間が雑音で埋まって話者交代を見つけられず、入力が長いまま（中央値 5〜10 秒、最大 20 秒）で CER 60〜67% だった。雑音の床を基準にした間の検出と、VAD のしきい値の引き下げ（自前の検出）で 26〜41% になり、正解区間で切った場合の 1.5 倍以内に入った。残る差は主に相手の声（カフェで CER 59%、屋外 52%）: 装着者より小さく雑音に埋もれ、細かく切られて文脈が減るか、取りこぼされる。
- 雑音・距離の影響は「正解区間で切った場合」で比べられる: 近接 12% → 腕 16% → 擦れ 21% → 1 日 23% → オフィス 26% → 屋外 27% → カフェ 31%。相手の声（本人より 8 dB 小さい）は雑音下で落ちやすく、カフェ・屋外では検出漏れが出る。
- 処理速度はこの PC で RTF 0.016〜0.052（1 時間の音声を 1〜3 分、#68 の修正後）。#71 の修正後の値は並行実行の影響が大きく比較できない。実機の速度は別途計測する。

## 6. 限界

- **合成音声は本物の会話ではない。** 読み上げ調で、言い直し・笑い・語尾の消え入り・方言・早口がほとんどない。数値は「合成音声でパイプラインが壊れていないか、条件でどれだけ悪化するか」の比較用で、実際の会話の精度の予測ではない。実際の会話での精度は実機と実録音で確かめる（`needs-device`）。
- 合成音声のくせ（Kokoro の一部の音声は文頭・文末が崩れることがある）が誤りに含まれる。話者（音声）ごとの差もある。
- 距離・残響・雑音・擦れ音は単純なモデル。実際の Watch のマイク特性、AGC、風切り音防止の処理、体による遮蔽は再現していない。
- 「発話外の誤認識」は会話の外の区間だけを数える。会話中の雑音から出た誤認識は CER の挿入誤りに含まれる。
- ReazonSpeech はテレビ音声で、ASR モデル（ReazonSpeech で学習）にとって有利な領域。学習に使われていないテスト分割を使う。
